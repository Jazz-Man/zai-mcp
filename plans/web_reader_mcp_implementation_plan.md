# Детальний план реалізації MCP сервера для Web Reader API

## Етап 1: Підготовка інфраструктури
1. **Налаштування проекту**
   - Оновлення `package.json` з необхідними залежностями (@effect/ai, @effect/platform-bun, тощо)
   - Налаштування `tsconfig.json` для підтримки Effect бібліотек
   - Налаштування `bunfig.toml` для оптимальної роботи з Bun

2. **Створення структури проекту**
   - `src/types.ts` - типи для JSON-RPC 2.0, MCP та Web Reader API
   - `src/config.ts` - конфігураційна система з підтримкою змінних середовища
   - `src/middleware.ts` - загальні функції для аутентифікації та логування

## Етап 2: Реалізація HTTP/SSE сервера
1. **Створення базового сервера**
   - `src/server.ts` - HTTP сервер на Bun з підтримкою SSE
   - Реалізація endpoint для прийому MCP запитів через SSE
   - Обробка JSON-RPC 2.0 повідомлень

2. **Обробка SSE потоків**
   - Реалізація ReadableStream для відправки результатів назад до клієнта
   - Обробка багатокористувацьких з'єднань
   - Керування станом з'єднань

## Етап 3: Інтеграція з Web Reader API
1. **Створення Web Reader клієнта**
   - `src/webReader.ts` - функції для виклику Web Reader API
   - Використання правильного URL для Coding плану: `/coding/paas/v4/reader`
   - Реалізація аутентифікації через Bearer токен
   - Обробка всіх параметрів запиту (url, timeout, no_cache, тощо)

2. **Перетворення MCP запитів**
   - Функції для перетворення MCP інструмент викликів у Web Reader API запити
   - Валідація параметрів перед відправленням

## Етап 4: MCP інтеграція
1. **Реєстрація інструменту**
   - Створення опису інструменту для читання веб-сторінок
   - Визначення схеми параметрів (обов'язковий URL, опційні параметри)
   - Реєстрація інструменту у MCP сервері

2. **Обробка викликів інструментів**
   - Логіка для обробки викликів інструменту читання URL
   - Передача результатів назад до MCP клієнта

## Етап 5: Обробка помилок та тестування
1. **Система обробки помилок**
   - Обробка помилок аутентифікації
   - Обробка мережевих помилок
   - Обробка помилок валідації параметрів
   - Таймаут та скасування запитів

2. **Тестування**
   - Створення тестових сценаріїв
   - Тестування різних типів URL
   - Тестування обробки помилок

## Етап 6: Деплой та документація
1. **Підготовка до використання**
   - Створення інструкцій з налаштування для Coding плану
   - Документація з необхідними змінними середовища
   - Приклади використання

2. **Конфігурація для Coding плану**
   - Вказівка правильного базового URL: `https://api.z.ai/api/coding/paas/v4/`
   - Правильна аутентифікація для Coding плану

Цей план враховує специфічні особливості Z.AI MCP сервера, який використовує SSE з JSON-RPC 2.0, але не підтримує стандартні MCP методи. Архітектура будується навколо технологічного стеку Bun.sh + @effect/ai + @effect/platform-bun + Effect, що забезпечить надійність та функційну архітектуру.

Важливо врахувати, що для Coding плану необхідно використовувати спеціальний URL `/coding/paas/v4/reader` замість загального `/paas/v4/reader`, щоб коректно використовувати передплату.
