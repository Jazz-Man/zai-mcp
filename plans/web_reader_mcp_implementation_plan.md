# Детальний план реалізації MCP сервера для Web Reader API

## Етап 1: Підготовка інфраструктури
1. **Налаштування проекту**
   - Оновлення `package.json` з необхідними залежностями (@effect/ai, @effect/platform-bun, тощо)
   - Налаштування `tsconfig.json` для підтримки Effect бібліотек
   - Налаштування `bunfig.toml` для оптимальної роботи з Bun

2. **Створення структури проекту**
   - `src/config.ts` - конфігураційна система з підтримкою змінних середовища (вже створено)
   - `src/schemas/common.ts` - спільні схеми для помилок (вже створено)
   - `src/services/http-client.ts` - HTTP клієнт для взаємодії з API (вже створено)
   - `src/services/web-reader.ts` - сервіс для Web Reader API (наступний етап)
   - `src/tools/web-reader.ts` - MCP інструмент для Web Reader (наступний етап)
   - `src/index.ts` - головний MCP сервер (наступний етап)

## Етап 2: Реалізація Web Reader сервісу
1. **Створення Web Reader сервісу**
   - `src/services/web-reader.ts` - функції для виклику Web Reader API
   - Використання правильного URL для Coding плану: `/coding/paas/v4/reader`
   - Використання наявного `ZaiHttpClient` для аутентифікації та обробки запитів
   - Обробка всіх параметрів запиту (url, timeout, no_cache, тощо)
   - Валідація вхідних даних за допомогою схем Effect

2. **Створення схем для Web Reader**
   - Схеми для запиту та відповіді Web Reader API відповідно до OpenAPI специфікації
   - Використання `effect/Schema` для типобезпеки

## Етап 3: MCP інтеграція
1. **Створення MCP інструменту**
   - `src/tools/web-reader.ts` - MCP інструмент для Web Reader
   - Використання `@effect/ai/Tool` для створення інструменту
   - Реєстрація інструменту з правильними схемами параметрів

2. **Налаштування MCP сервера**
   - `src/index.ts` - реалізація MCP сервера з використанням `@effect/ai/McpServer`
   - Підключення Web Reader інструменту
   - Налаштування stdio транспорту для MCP протоколу

## Етап 4: Обробка помилок та тестування
1. **Система обробки помилок**
   - Використання наявних схем помилок (NetworkError, ApiError)
   - Обробка помилок аутентифікації
   - Обробка мережевих помилок
   - Обробка помилок валідації параметрів

2. **Тестування**
   - Розширення наявних тестів для перевірки Web Reader функціональності
   - Створення тестів для MCP інструменту
   - Тестування різних типів URL
   - Тестування обробки помилок

## Етап 5: Деплой та документація
1. **Підготовка до використання**
   - Створення інструкцій з налаштування для Coding плану
   - Документація з необхідними змінними середовища
   - Приклади використання

2. **Конфігурація для Coding плану**
   - Вказівка правильного базового URL: `https://api.z.ai/api/coding/paas/v4/`
   - Правильна аутентифікація для Coding плану

Цей оновлений план враховує наявну інфраструктуру проекту, зокрема вже створені компоненти:
- Конфігураційна система (ZaiConfigService)
- HTTP клієнт (ZaiHttpClient) з підтримкою аутентифікації та обробки помилок
- Система схем для помилок
- Тестова інфраструктура

Архітектура будується навколо технологічного стеку Bun.sh + `@effect/ai` + `@effect/platform-bun` + Effect, що забезпечить надійність та функційну архітектуру.

Важливо врахувати, що для Coding плану необхідно використовувати спеціальний URL `/coding/paas/v4/reader` замість загального `/paas/v4/reader`, щоб коректно використовувати передплату.
